# 圖卡審稿規則（AI 審稿員）

> 2026-08-18 立，依當日圖卡設計研究（一卡一重點、行動端可讀性、視覺一致性）。
> 執行者：AUTOPILOT 排程 session 在發布前，用 Read 工具逐張看渲染好的 PNG，8 項全過才准發。
> 機器檢（字數閘門、溢版偵測）在 `bin/render-cards.mjs` 裡，跑不過根本到不了這一步。

## 8 項檢查（逐張看圖，全 pass 才發）

1. **一卡一重點**：一張卡只講一件事。塞了兩個主題＝fail
2. **焦點唯一**：3 秒內找得到這張卡的視覺重心（大標或反白塊），而且只有一個
3. **不擠**：留白目測 ≥ 1/3 卡面；字沒有貼到外框
4. **折行乾淨**：沒有孤字掉行（單一個字自己一行）、詞沒被折斷在奇怪的地方
5. **整組一致**：每張同版式同色同字體；Day 徽章數字對、頁碼連續、`@yrrah9_` 都在
6. **封面 3 秒測試**：只看封面就說得出「這篇給我什麼」；封面的承諾後面卡片有接住
7. **內容對得上查證**：卡上的說法跟步驟 5 的查證結果一致；指令拼字逐字元核對
8. **卡序收得住**：卡片順著封面走，最後一張是收束（產出／結果／清單），不是講到一半斷掉

## 失敗處置（每日必發，2026-08-18 使用者裁決）

- 任一項 fail → 改 spec JSON 重渲染，**同題材最多重產 2 次**
- 仍不過 → **換題材**，回每日流程步驟 4 重跑，**最多換到第 3 個題材**
- 三個題材全炸（6 輪）→ 推播請人工處理。這是唯一允許斷更的情境
- 每次 fail 把「哪張卡、哪一項、為什麼」寫進當日 log，人工回顧用

## 機器檢摘要（詳見 render-cards.mjs 開頭註解）

- **字數閘門**（exit 2）：每卡型每欄位上限寫死在 `LIMITS`，超標列出清單退回
- **溢版偵測**（exit 3）：渲染後量畫布與每個元素，內容超出容器＝fail
- 改模板或上限前先想：行動端內文 ≥28px、標題 ≥60px、四邊留白 ≥60px 是研究底線，不要往下修
